# Data Model: Alexa+ Voice Appeal Assistant (MCP)

All entities live in **server memory** for the lifetime of a case (FR-040). Nothing is
persisted. Types reuse feature-001 schemas where they exist (`lib/schemas/*`).

## Case

| Field | Type | Notes |
|---|---|---|
| `code` | `CaseCode` (6 chars, alphabet `ACFHJKMNQRWXY234679`) | Spoken handle; unique 24 h |
| `sessionId` | string | MCP session that owns the case; tools reject other sessions |
| `status` | enum below | State machine |
| `path` | `"document" \| "sample" \| "no_document"` | How facts are established |
| `extraction` | `Extraction` (001) \| null | From `extractDocument` or a sample's golden file |
| `answers` | `Answers` (001, partial) | Spoken answers; `state` required for `no_document` |
| `approxDocumentDate` | ISO date \| null | `no_document` only; marks deadlines approximate |
| `situation` | `Situation` (001) \| null | Built by `buildSituation` once answers suffice |
| `rights` | `RightsResult` (001) \| null | From `computeRights`, never edited |
| `readbacks` | `Readback[]` | Every fact set read back and its yes/no |
| `letter` | `LetterDraft` (001) \| null | From `draftLetter` |
| `delivery` | `Delivery` \| null | Outcome of send |
| `account` | `{ emailMasked: string; email: string }` | From Cognito userInfo; `email` never returned by any tool |
| `createdAt`, `lastActivityAt`, `expiresAt` | timestamps | `expiresAt = lastActivityAt + 30 min` |

### Status transitions

```
started ──(has document)──► awaiting_document ──(attach_document / use_sample)──► facts_pending
started ──(no document)───► answering ─────────(answers complete)──────────────► facts_pending
facts_pending ──(confirm_facts yes)──► facts_confirmed ──(compute_rights)──► rights_computed
facts_pending ──(confirm_facts no + correction)──► facts_pending
rights_computed ──(draft_letter confirmed)──► letter_drafted ──(send_letter confirmed)──► sent
any ──(discard_case confirmed | 30 min idle)──► discarded   (memory freed, code blocked 24 h)
awaiting_document ──(two check-ins without upload)──► offers `no_document` (status unchanged until user picks)
```

Validation: `compute_rights` requires `facts_confirmed`; `draft_letter` requires
`rights_computed`; `send_letter` requires `letter_drafted`; a `sent` or `discarded` case answers
every tool with `case_closed`.

## Readback

| Field | Type |
|---|---|
| `kind` | `"document_facts" \| "answer" \| "correction"` |
| `spoken` | string ≤ 40 words — generated deterministically from fields (template, not LLM) |
| `fields` | the exact field values read back |
| `confirmed` | `true \| false \| null` |
| `at` | timestamp |

## SpokenRightsSummary (tool output, derived — not stored beyond `rights`)

| Field | Type | Notes |
|---|---|---|
| `firstDeadline` | `{ date, daysRemaining, anchorDate, anchorLabel, ruleId, sourceName, approximate }` | Earliest of `rights.deadlines` |
| `otherDeadlines` | same[] | For the written summary |
| `protections` | `{ id, spoken (≤ 2 sentences), sourceName, sourceUrl, whyApplies }[]` | Ordered as the 001 engine orders them |
| `chunks` | `string[]` | Pre-chunked ≤ 120-word spoken blocks for "more" |
| `humanHelp` | `{ name, phone?, url, spoken }` | From `data/help-resources.json` |

`spoken` strings are produced by templates over the 001 rule `summary` fields; the LLM never
rephrases a rule (FR-013).

## ToolResult envelope (every tool)

```
{ ok: true,  case: { code, status }, data: <tool-specific>, speak?: string }
{ ok: false, case?: { code, status }, error: { code, message, speak } }
{ ok: false, needs_confirmation: { action, question, expectedYes: ["yes","yeah","correct","that's right"], expectedNo: [...] } }
```

`speak` is a suggested ≤ 60-word utterance the assistant may use verbatim; it is generated by
templates so that facts, deadlines and sources never pass through the LLM's paraphrase. Error
codes: `case_not_found`, `case_closed`, `wrong_session`, `wrong_state`, `unsupported_document`,
`unsupported_coverage`, `model_unavailable`, `unsupported_on_provider`, `delivery_failed`.

## Rules dataset release (external repo)

`schema.json`, `rules/*.json` (unchanged 001 shape: `id, jurisdiction, summary, legal_reference,
source_url, last_verified, applies_when, computes?`), `VERSION`; Overturn keeps
`data/rules/RULES_VERSION` and fails its test if the vendored files differ from that tag.
